# Governance

OpenWorkSpace is intended to be a community-developed open-source project. During pre-alpha, repository maintainers coordinate releases, review contributions, and document decisions publicly.

- Small, reversible changes may use ordinary pull-request review.
- Architectural, security, compatibility, licensing, and governance changes require a public design proposal before implementation.
- Significant decisions should be recorded in `architecture/decision-records/` with context, alternatives, consequences, and status.
- Security-sensitive changes require focused review and tests. Convenience is not a reason to weaken default-deny behavior.

Maintainers should keep project status accurate, review contributions consistently, protect private vulnerability reports, document release evidence, and avoid implying unimplemented capabilities are available.

Participation is open under the repository license and Code of Conduct. No contributor is required to use a hosted OpenWorkSpace service. The project does not currently operate one.
